# 素材包目录与修订合同

根目录 [manifest.json](../manifest.json) 继续保存全量 v1 清单，`collection` 保持原值。旧导入工具只需读取它与 `emoticons/`，不要求理解 [packs.json](../packs.json)。[packs/curated.json](../packs/curated.json) 是同格式的精选清单，所有图片路径仍相对仓库根目录，原图不复制到 `packs/`。精选清单按实际画面逐张复核，复核范围与移除记录见[精选复核记录](curated-review.md)。

## 标准 v1 清单

顶层字段为 `schema_version: 1`、字符串 `collection` 和数组 `items`。每项字段如下：

| 字段 | 约束 |
| --- | --- |
| `md5` | 32 位小写十六进制，同一清单内唯一 |
| `sha256` | 64 位小写十六进制，校验原始图片字节 |
| `filename` | 精确等于 `emoticons/<md5>.<format>`，不能使用绝对路径、反斜杠或 `..` |
| `format` | `gif`、`png`、`jpg`、`webp` |
| `size` | 原图字节数，正整数，最多 32 MiB |
| `caption` | 可省略的 UTF-8 字符串，最多 4,096 字节；始终作为数据处理 |

清单最多 8 MiB、20,000 项；条目按 MD5 升序排列。拒绝重复 JSON 键、不合法 UTF-8 与未知版本；未知非必需字段可忽略。更新清单只写已定义字段，不添加修订字段。图片身份由 MD5 与 SHA-256 共同核对，格式签名和哈希不能代替画面、动画可解码性检查。

## 包目录

`packs.json` 是最多 8 MiB 的 UTF-8 JSON，顶层为 `schema_version: 1` 与 `packs` 数组。每包包含：

| 字段 | 约束 |
| --- | --- |
| `id` | 匹配 `[a-z][a-z0-9_-]{0,63}`，目录内唯一 |
| `name`、`description` | 非空名称和描述 |
| `manifest` | `all` 指向 `manifest.json`，其他包指向 `packs/<id>.json` |
| `manifest_sha256` | 清单文件原始字节的 SHA-256，64 位小写十六进制，也是包修订号 |
| `count` | 清单条目数，非负整数 |
| `size` | 清单中图片 `size` 之和，非负整数，不含清单字节数 |

本仓库必须提供 `all` 和 `curated`，每个分包均为全量清单的原图子集。分包可独立完善描述，原图的路径、格式、大小与双哈希必须一致。

消费者先核对 `manifest_sha256`，再解析同一份字节，最后逐图校验。空白、换行、字段顺序和描述变化都会产生新修订；不能解析后重新序列化再计算修订。修订值不写入被哈希的清单，避免自引用。源更新造成不匹配时应失败，下次显式调用重新读取目录，不混用不同版本。目录和原图可以从同一个 HTTPS 根地址按相对路径获取，不要求克隆仓库或调用托管平台 API。

## 维护与验证

维护时结束其他写入或更新，使用完整本地副本。先保存原图、更新全量清单，再更新分包清单；所有原图只保留在 `emoticons/`。只改描述时保留原图和内容哈希。修改清单后执行：

```bash
python3 scripts/validate_packs.py --refresh
python3 scripts/validate_packs.py
python3 -m unittest discover -s scripts -p 'test_*.py' -v
git diff --check
```

`--refresh` 在验证全部清单、子集关系和原图后，更新目录的修订、数量和总字节数。它不会修改清单或图片，也不会修复错误哈希。默认校验模式只读，并在解析包清单前核对其声明修订。两种模式都拒绝缺图、未登记文件、重复条目、路径越界和目录内符号链接。

提交时同时包含发生变化的原图、清单与目录。全量校验读取约 1 GiB 原图，适合维护或首次安装，日常选图无需重复执行。此脚本用于停止其他写入后的本地维护，不承担并发安全的安装发布。通过校验只说明文件一致，不表示画面或描述已经复核。
